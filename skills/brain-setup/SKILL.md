# brain-setup: สร้างสมองบริษัทชุดเริ่มต้น

ใช้เฉพาะ MCP tools ของ connector **Limitless Company Brain** (ใน Claude Code ชื่อจะเป็น `mcp__limitless-brain__<tool>`). ไม่ใช้ shell และไม่อ้าง path ในเครื่อง

## กฎเหล็ก
- ห้ามเขียนทับโน้ตที่มีเนื้อหาอยู่แล้ว ตรวจก่อนทุกครั้ง มีแล้วให้ข้าม
- ห้ามลบ ย้าย หรือเปลี่ยนชื่อของเดิม
- โน้ตที่มีอยู่แล้ว แก้ได้ด้วย `edit_note` พร้อม `expectedRevision` เท่านั้น ห้ามใช้ `update_note`
- ห้ามแต่งข้อมูลบริษัทเอง ช่องที่ยังไม่รู้ให้คง `【กรอก: ...】` ไว้ตามเดิม

## 1. หา vault และอ่านของเดิม
1. `list_vaults` เพื่อได้ `vaultId` ถ้ามีหลาย vault ให้ถามผู้ใช้ว่าใช้อันไหน
2. `list_folders` (vaultId) เก็บ path ของโฟลเดอร์ที่มีอยู่
3. `list_notes` (vaultId, `limit` 200, ตาม `nextCursor` จนเป็น null) เก็บ `relPath` ของโน้ตที่มีอยู่
4. ถ้ามี `00 Start here/00 Start here.md` หรือ `_AI/How to use this brain.md` อยู่แล้ว ให้ `read_note` อ่านก่อน (vault นี้อาจตั้งไว้แล้ว)
5. ถ้า vault มีโน้ตอยู่แล้วเกิน 30 โน้ต ให้บอกผู้ใช้และถามก่อนว่าจะเพิ่มโครงนี้ลงไปไหม
6. ดูว่ามีโน้ตที่ relPath คือ `AGENTS.md` พอดีไหม (อยู่ชั้นบนสุดของ vault ไม่อยู่ในโฟลเดอร์ใด เทียบแบบไม่สนตัวพิมพ์เล็กใหญ่) vault ที่สร้างจากแอปจะมีไฟล์นี้เป็นแผนที่โฟลเดอร์สำหรับ AI จำไว้ว่า "มี" หรือ "ไม่มี" เพื่อใช้ในขั้น 4

## 2. สร้างโฟลเดอร์ที่ยังไม่มี
`create_folder` (vaultId, name, path) ทีละโฟลเดอร์ ชื่อกับ path เหมือนกันเพราะอยู่ชั้นบนสุด:

`00 Start here`, `SOP`, `FAQ`, `Products & prices`, `Customers`, `Meetings`, `Decisions`, `Team`, `_AI`

ถ้าได้ `adopted: true` แปลว่ามีอยู่แล้ว นับเป็น "ข้าม"

## 3. สร้างโน้ตที่ยังไม่มี
อ่านเนื้อหาแม่แบบ: ถ้าเปิดไฟล์ในโฟลเดอร์ `templates/` ข้าง SKILL.md นี้ได้ ให้อ่านจากตรงนั้น ถ้าเปิดไม่ได้ (เช่นใช้ผ่านแอป Claude) ให้ใช้ `read_skill_file` (name `brain-setup`, path ตามตาราง)

| โน้ตใน vault (relPath) | แม่แบบ |
|---|---|
| `00 Start here/00 Start here.md` | `templates/00-start-here.md` |
| `_AI/How to use this brain.md` | `templates/how-to-use-this-brain.md` |
| `SOP/SOP ขาย & ราคา.md` | `templates/sop-sales-prices.md` |
| `FAQ/FAQ ราคา & ส่วนลด.md` | `templates/faq-prices-discounts.md` |
| `Decisions/{{วันนี้}} ตัวอย่าง ส่วนลดลูกค้า VIP.md` | `templates/decision-example.md` |

แม่แบบไม่มีบรรทัดหัวข้อ `# ชื่อโน้ต` เพราะแอปแสดงชื่อไฟล์เป็นชื่อโน้ตอยู่แล้ว ห้ามเติมหัวข้อนั้นเอง

ก่อนสร้าง แทน `{{วันนี้}}` ทุกจุด (ทั้งในชื่อโน้ตและเนื้อหา) ด้วยวันที่วันนี้แบบ `YYYY-MM-DD` ปี ค.ศ. ตามเวลาไทย ไม่แน่ใจวันที่ให้ถามผู้ใช้

ทีละโน้ต:
- มี relPath นี้อยู่แล้ว (เทียบแบบไม่สนตัวพิมพ์เล็กใหญ่): `read_note` ถ้ามีเนื้อหาให้ข้าม ถ้าว่างให้สร้างต่อได้
- โน้ตตัวอย่างใน Decisions: ถ้ามีโน้ตใน `Decisions/` ที่ชื่อมีคำว่า `ตัวอย่าง ส่วนลดลูกค้า VIP` อยู่แล้ว (วันไหนก็ได้) ให้ข้าม
- ยังไม่มี: `create_note` (vaultId, relPath, content = เนื้อหาแม่แบบ)
- ผลตอบกลับ `adopted: true` กับ `seeded: false` แปลว่ามีของเดิมอยู่แล้วและไม่ได้เขียนอะไร นับเป็น "ข้าม"

## 4. เชื่อมกับ `AGENTS.md` (เฉพาะ vault ที่มี `AGENTS.md` ชั้นบนสุด)
ถ้าขั้น 1 ไม่พบ `AGENTS.md` ที่ชั้นบนสุด ให้ข้ามขั้นนี้ทั้งหมด ไม่สร้าง `AGENTS.md` ใดๆ และไม่ต้องพูดถึงเรื่องนี้ในรายงาน

`AGENTS.md` ชั้นบนสุดคือแผนที่โฟลเดอร์ที่ AI ทุกตัวอ่านก่อน และแต่ละโฟลเดอร์มี `AGENTS.md` ของตัวเองเป็นสารบัญโน้ต ขั้นนี้ทำให้โฟลเดอร์ทั้ง 9 อยู่ในแผนที่นั้น

| โฟลเดอร์ | สารบัญ (relPath) | แม่แบบ | ข้อความช่องแรกของแถวในแผนที่ |
|---|---|---|---|
| `00 Start here` | `00 Start here/AGENTS.md` | `templates/agents/00-start-here.md` | ภาพรวมบริษัท อ่านก่อนทุกครั้ง |
| `SOP` | `SOP/AGENTS.md` | `templates/agents/sop.md` | ขั้นตอนการทำงาน |
| `FAQ` | `FAQ/AGENTS.md` | `templates/agents/faq.md` | คำถามที่ลูกค้าและทีมถามบ่อย |
| `Products & prices` | `Products & prices/AGENTS.md` | `templates/agents/products-prices.md` | สินค้า แพ็กเกจ ราคา |
| `Customers` | `Customers/AGENTS.md` | `templates/agents/customers.md` | ข้อมูลลูกค้า |
| `Meetings` | `Meetings/AGENTS.md` | `templates/agents/meetings.md` | บันทึกประชุม |
| `Decisions` | `Decisions/AGENTS.md` | `templates/agents/decisions.md` | การตัดสินใจ (มีวันที่ทุกเรื่อง) |
| `Team` | `Team/AGENTS.md` | `templates/agents/team.md` | คนในทีม และงานของแต่ละคน |
| `_AI` | `_AI/AGENTS.md` | `templates/agents/ai.md` | กฎที่ AI ต้องทำตาม (`_AI/How to use this brain.md`) และรายการงานของ AI |

### 4.1 สร้างสารบัญของแต่ละโฟลเดอร์
ทำกับโฟลเดอร์ในตารางที่มีอยู่จริงหลังขั้น 2 ทีละโฟลเดอร์ อ่านแม่แบบด้วยวิธีเดียวกับขั้น 3:
- มีสารบัญอยู่แล้วและมีเนื้อหา: ข้าม ห้ามเขียนทับ ถ้าขั้น 3 เพิ่งสร้างโน้ตในโฟลเดอร์นั้น และตาราง `## Notes` ยังไม่มีแถวของโน้ตนั้น ให้เพิ่มแถวด้วย `edit_note` แบบ `insert_after` วิธีเดียวกับข้อ 4.2
- ยังไม่มี หรือมีแต่ว่าง: แทน `{{วันนี้}}` แล้วทำตาราง `## Notes` ให้ตรงกับโน้ตที่มีอยู่จริงในโฟลเดอร์นั้น (ไม่นับ `AGENTS.md` และไม่นับโน้ตในโฟลเดอร์ย่อย) จากนั้น `create_note` (vaultId, relPath, content)
  - โน้ตในแม่แบบที่ไม่มีอยู่จริง: ตัดแถวนั้นออก
  - โน้ตตัวอย่างใน Decisions ที่มีอยู่ก่อนแล้วด้วยวันที่อื่น: ใช้ชื่อไฟล์จริงในแถว
  - โน้ตที่มีอยู่จริงแต่ไม่มีแถว: เพิ่มแถว ช่องที่สองเขียนสั้นๆ จากชื่อโน้ตเท่านั้น ห้ามเดาเนื้อหา
- ส่วนอื่นของแม่แบบ (หัวไฟล์ระหว่าง `---` หัวข้อ `## Notes` และ `## Rules`) ใช้ตามเดิม ไม่แปลและไม่ตัดออก

### 4.2 เพิ่มแถวในแผนที่โฟลเดอร์
1. `read_note` โน้ต `AGENTS.md` ชั้นบนสุด เก็บ `revision`
2. หาตารางแผนที่: ตารางที่มีหัวตาราง `| What it is | Where it goes | Read first |` (อยู่ใต้หัวข้อ `## Knowledge Routing`) ถ้าหาไม่เจอ แปลว่าเจ้าของแก้ไฟล์นี้ไปแล้ว ห้ามเดาและห้ามเขียนอะไรลงไฟล์นี้ ให้ข้ามข้อ 4.2 แล้วบอกในรายงานว่า "ยังไม่ได้เพิ่มโฟลเดอร์ใหม่ลงแผนที่ เพราะไม่พบตารางแผนที่ใน AGENTS.md"
3. โฟลเดอร์ไหนมีแถวอยู่แล้ว (ช่องที่สองเป็น `<โฟลเดอร์>/` เทียบแบบไม่สนตัวพิมพ์เล็กใหญ่) ให้ข้ามโฟลเดอร์นั้น ถ้ามีครบทุกโฟลเดอร์แล้ว ไม่ต้องเรียก `edit_note`
4. เขียนแถวใหม่ของโฟลเดอร์ที่ยังไม่มีแถว เรียงตามตารางข้างบน แถวละบรรทัด รูปแบบ:
   ``| <ข้อความช่องแรก> | `<โฟลเดอร์>/` | `<โฟลเดอร์>/AGENTS.md` |``
   โฟลเดอร์ที่ไม่มีอยู่จริงไม่ต้องมีแถว โฟลเดอร์ที่สร้างสารบัญไม่สำเร็จให้เว้นช่องที่สามว่าง
5. `edit_note` ครั้งเดียว (docId, `expectedRevision`, edits = หนึ่งรายการแบบ `insert_after` โดย `anchor` คือแถวสุดท้ายของตารางแผนที่ทั้งบรรทัด คัดลอกจากโน้ตแบบตรงตัว และ `text` คือขึ้นบรรทัดใหม่หนึ่งครั้ง ตามด้วยแถวใหม่ทั้งหมด)
6. ห้ามแก้หรือลบแถวเดิม (รวมแถวของ `Getting Started/`, `Concepts/`, `Examples/`) และห้ามแตะข้อความส่วนอื่นของไฟล์
7. ถูกปฏิเสธด้วย `stale_revision` หรือ `anchor_not_found`: `read_note` ใหม่ ทำข้อ 2 ถึง 5 อีกครั้งเดียว ถ้ายังไม่ได้ ให้ใส่ในรายงานกลุ่ม "ไม่สำเร็จ"

## 5. รายงาน
บอกผู้ใช้เป็นภาษาไทยง่ายๆ 3 กลุ่ม:
- สร้างแล้ว: รายการโฟลเดอร์และโน้ต ถ้าทำขั้น 4 ให้บอกด้วยว่าสร้างสารบัญ `AGENTS.md` ในโฟลเดอร์ไหนบ้าง และเพิ่มกี่แถวในแผนที่โฟลเดอร์ พร้อมอธิบายหนึ่งประโยคว่า `AGENTS.md` คือแผนที่ที่บอก AI ว่าข้อมูลแบบไหนเก็บที่โฟลเดอร์ไหน
- ข้าม เพราะมีอยู่แล้ว: รายการ
- ไม่สำเร็จ: รายการพร้อมเหตุผล (`no_access` หรือ `read_only` แปลว่าบัญชีนี้ไม่มีสิทธิ์แก้ vault นี้ ให้เจ้าของ vault เป็นคนรัน)

ย้ำว่าโน้ตใน SOP, FAQ และ Decisions เป็น **ตัวอย่าง** ให้แทนที่ด้วยข้อมูลจริงของบริษัท

## 6. ชวนกรอกหน้า Start here
ถามผู้ใช้: "อยากให้ช่วยกรอกหน้า 00 Start here ไหม ถามทีละข้อ 10 ข้อ ข้ามข้อไหนก็ได้"

ถ้าตกลง ถามทีละข้อ รอคำตอบก่อนถามข้อถัดไป:
1. บริษัทชื่ออะไร ขายอะไร (1-2 ประโยค)
2. ลูกค้าหลักคือใคร
3. สินค้าหรือแพ็กเกจหลัก และราคา
4. ส่วนลดสูงสุดที่ให้ได้ และใครเป็นคนอนุมัติ
5. ขายผ่านช่องทางไหนบ้าง
6. น้ำเสียงเวลาคุยกับลูกค้า (เช่น เป็นกันเอง สุภาพ ลงท้ายคะ/ครับ)
7. คำหรือเรื่องที่ห้ามพูดหรือห้ามสัญญากับลูกค้า
8. ใครดูแลเรื่องอะไร (ชื่อเล่น และหน้าที่)
9. เวลาทำการ และช่องทางติดต่อของบริษัท
10. เรื่องที่พนักงานใหม่ต้องรู้ในวันแรก

หลังได้คำตอบแต่ละข้อ:
1. `read_note` หน้า Start here เพื่อได้ `revision`
2. `edit_note` (docId, `expectedRevision`, edits = replace โดย `find` คือช่อง `【กรอก: ...】` ของข้อนั้นแบบตรงตัว และ `replace` คือคำตอบ)
3. ใช้คำของเจ้าของ ไม่แต่งเพิ่ม ข้อที่เจ้าของข้ามให้คงช่องไว้
4. ถ้าถูกปฏิเสธด้วย `stale_revision` หรือ `anchor_not_found` ให้อ่านโน้ตใหม่แล้วลองอีกครั้ง

ข้อ 3 ถ้าราคามีมากกว่า 5 รายการ ให้ถามว่าจะเก็บรายการเต็มไว้ที่ `Products & prices/ราคาสินค้า.md` ไหม ถ้าเก็บ ให้ใส่ลิงก์ `[[ราคาสินค้า]]` ในหน้า Start here และถ้ามี `Products & prices/AGENTS.md` ให้เพิ่มแถวของโน้ตนี้ในตาราง `## Notes` ด้วย `edit_note` วิธีเดียวกับข้อ 4.2

จบแล้วสรุปว่ากรอกข้อไหนแล้ว ข้อไหนยังว่าง และแนะนำขั้นต่อไป: "แก้โน้ต SOP ขาย & ราคา ให้เป็นราคาจริงของบริษัทวันนี้เลย"
