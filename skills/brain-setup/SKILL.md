# brain-setup: สร้างสมองบริษัทชุดเริ่มต้น

ใช้เฉพาะ MCP tools ของ connector **Limitless Company Brain** (ใน Claude Code ชื่อจะเป็น `mcp__limitless-brain__<tool>`). ไม่ใช้ shell และไม่อ้าง path ในเครื่อง

## กฎเหล็ก
- ห้ามเขียนทับโน้ตที่มีเนื้อหาอยู่แล้ว ตรวจก่อนทุกครั้ง มีแล้วให้ข้าม
- ห้ามลบ ย้าย หรือเปลี่ยนชื่อของเดิม
- ห้ามแต่งข้อมูลบริษัทเอง ช่องที่ยังไม่รู้ให้คง `【กรอก: ...】` ไว้ตามเดิม

## 1. หา vault และอ่านของเดิม
1. `list_vaults` เพื่อได้ `vaultId` ถ้ามีหลาย vault ให้ถามผู้ใช้ว่าใช้อันไหน
2. `list_folders` (vaultId) เก็บ path ของโฟลเดอร์ที่มีอยู่
3. `list_notes` (vaultId, `limit` 200, ตาม `nextCursor` จนเป็น null) เก็บ `relPath` ของโน้ตที่มีอยู่
4. ถ้ามี `00 Start here/00 Start here.md` หรือ `_AI/How to use this brain.md` อยู่แล้ว ให้ `read_note` อ่านก่อน (vault นี้อาจตั้งไว้แล้ว)
5. ถ้า vault มีโน้ตอยู่แล้วเกิน 30 โน้ต ให้บอกผู้ใช้และถามก่อนว่าจะเพิ่มโครงนี้ลงไปไหม

## 2. สร้างโฟลเดอร์ที่ยังไม่มี
`create_folder` (vaultId, name, path) ทีละโฟลเดอร์ ชื่อกับ path เหมือนกันเพราะอยู่ชั้นบนสุด:

`00 Start here`, `SOP`, `FAQ`, `Products & prices`, `Customers`, `Meetings`, `Decisions`, `Team`, `_AI`

ถ้าได้ `adopted: true` แปลว่ามีอยู่แล้ว นับเป็น "ข้าม"

## 3. สร้างโน้ตที่ยังไม่มี
อ่านเนื้อหาแม่แบบ: ถ้าเปิดไฟล์ในโฟลเดอร์ `templates/` ข้าง SKILL.md นี้ได้ ให้อ่านจากตรงนั้น ถ้าเปิดไม่ได้ (เช่นใช้ผ่านแอป Claude) ให้ใช้ `read_skill_file` (name `brain-setup`, path ตามตาราง)

| โน้ตใน vault (relPath) | แม่แบบ |
|---|---|
| `00 Start here/00 Start here.md` | `templates/00-start-here.md` |
| `_AI/How to use this brain.md` | `templates/how-to-use-this-brain.md` |
| `SOP/SOP ขาย & ราคา.md` | `templates/sop-sales-prices.md` |
| `FAQ/FAQ ราคา & ส่วนลด.md` | `templates/faq-prices-discounts.md` |
| `Decisions/{{วันนี้}} ตัวอย่าง ส่วนลดลูกค้า VIP.md` | `templates/decision-example.md` |

ก่อนสร้าง แทน `{{วันนี้}}` ทุกจุด (ทั้งในชื่อโน้ตและเนื้อหา) ด้วยวันที่วันนี้แบบ `YYYY-MM-DD` ปี ค.ศ. ตามเวลาไทย ไม่แน่ใจวันที่ให้ถามผู้ใช้

ทีละโน้ต:
- มี relPath นี้อยู่แล้ว (เทียบแบบไม่สนตัวพิมพ์เล็กใหญ่): `read_note` ถ้ามีเนื้อหาให้ข้าม ถ้าว่างให้สร้างต่อได้
- โน้ตตัวอย่างใน Decisions: ถ้ามีโน้ตใน `Decisions/` ที่ชื่อมีคำว่า `ตัวอย่าง ส่วนลดลูกค้า VIP` อยู่แล้ว (วันไหนก็ได้) ให้ข้าม
- ยังไม่มี: `create_note` (vaultId, relPath, content = เนื้อหาแม่แบบ)
- ผลตอบกลับ `adopted: true` กับ `seeded: false` แปลว่ามีของเดิมอยู่แล้วและไม่ได้เขียนอะไร นับเป็น "ข้าม"

## 4. รายงาน
บอกผู้ใช้เป็นภาษาไทยง่ายๆ 3 กลุ่ม:
- สร้างแล้ว: รายการโฟลเดอร์และโน้ต
- ข้าม เพราะมีอยู่แล้ว: รายการ
- ไม่สำเร็จ: รายการพร้อมเหตุผล (`no_access` หรือ `read_only` แปลว่าบัญชีนี้ไม่มีสิทธิ์แก้ vault นี้ ให้เจ้าของ vault เป็นคนรัน)

ย้ำว่าโน้ตใน SOP, FAQ และ Decisions เป็น **ตัวอย่าง** ให้แทนที่ด้วยข้อมูลจริงของบริษัท

## 5. ชวนกรอกหน้า Start here
ถามผู้ใช้: "อยากให้ช่วยกรอกหน้า 00 Start here ไหม ถามทีละข้อ 10 ข้อ ข้ามข้อไหนก็ได้"

ถ้าตกลง ถามทีละข้อ รอคำตอบก่อนถามข้อถัดไป:
1. บริษัทชื่ออะไร ขายอะไร (1-2 ประโยค)
2. ลูกค้าหลักคือใคร
3. สินค้าหรือแพ็กเกจหลัก และราคา
4. ส่วนลดสูงสุดที่ให้ได้ และใครเป็นคนอนุมัติ
5. ขายผ่านช่องทางไหนบ้าง
6. น้ำเสียงเวลาคุยกับลูกค้า (เช่น เป็นกันเอง สุภาพ ลงท้ายคะ/ครับ)
7. คำหรือเรื่องที่ห้ามพูดหรือห้ามสัญญากับลูกค้า
8. ใครดูแลเรื่องอะไร (ชื่อเล่น และหน้าที่)
9. เวลาทำการ และช่องทางติดต่อของบริษัท
10. เรื่องที่พนักงานใหม่ต้องรู้ในวันแรก

หลังได้คำตอบแต่ละข้อ:
1. `read_note` หน้า Start here เพื่อได้ `revision`
2. `edit_note` (docId, `expectedRevision`, edits = replace โดย `find` คือช่อง `【กรอก: ...】` ของข้อนั้นแบบตรงตัว และ `replace` คือคำตอบ)
3. ใช้คำของเจ้าของ ไม่แต่งเพิ่ม ข้อที่เจ้าของข้ามให้คงช่องไว้
4. ถ้าถูกปฏิเสธด้วย `stale_revision` หรือ `anchor_not_found` ให้อ่านโน้ตใหม่แล้วลองอีกครั้ง

ข้อ 3 ถ้าราคามีมากกว่า 5 รายการ ให้ถามว่าจะเก็บรายการเต็มไว้ที่ `Products & prices/ราคาสินค้า.md` ไหม ถ้าเก็บ ให้ใส่ลิงก์ `[[ราคาสินค้า]]` ในหน้า Start here

จบแล้วสรุปว่ากรอกข้อไหนแล้ว ข้อไหนยังว่าง และแนะนำขั้นต่อไป: "แก้โน้ต SOP ขาย & ราคา ให้เป็นราคาจริงของบริษัทวันนี้เลย"
