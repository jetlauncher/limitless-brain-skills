# weekly-brain-review: รีวิวสมองบริษัททุกวันศุกร์

ใช้เฉพาะ MCP tools ของ connector **Limitless Company Brain** (ใน Claude Code ชื่อจะเป็น `mcp__limitless-brain__<tool>`). ไม่ใช้ shell และไม่อ้าง path ในเครื่อง

ระหว่างตรวจ skill นี้**อ่านอย่างเดียว** เขียนได้แค่โน้ตรีวิว ห้ามแก้ ย้าย หรือลบโน้ตอื่น จะแก้โน้ตอื่นได้ก็ต่อเมื่อเจ้าของสั่งหลังอ่านรีวิวแล้ว (ดูข้อ 4)

## ทำไมเก็บที่ `_AI/Weekly review/` ไม่ใช่ `Decisions/`
- `Decisions/` ต้องเป็นบันทึกการตัดสินใจจริงที่มีวันที่ ซึ่ง AI ใช้เป็นที่มาของคำตอบ
- โน้ตรีวิวจงใจยกราคาที่ขัดกันมาวางคู่กัน ถ้าอยู่ใน `Decisions/` การค้นเรื่องราคาจะเจอตัวเลขผิดปนมา และรีวิวสัปดาห์หน้าจะนับมันเป็นความขัดแย้งเพิ่ม
- กฎใน `_AI/How to use this brain` บอกแล้วว่าโน้ตใน `_AI` ไม่ใช่ข้อเท็จจริง ห้ามใช้ตอบลูกค้า
- สิ่งที่เจ้าของตัดสินระหว่างรีวิว ให้บันทึกลง `Decisions/` ตามปกติด้วย brain-writeback

## อ่านก่อน
1. `list_vaults` เพื่อได้ `vaultId`
2. `list_notes` (pathPrefix `_AI/How to use this brain`) แล้ว `read_note` ทำตามกฎในนั้น
3. อ่าน `00 Start here/00 Start here` ด้วยวิธีเดียวกัน
4. อ่านโน้ตรีวิวล่าสุดใน `_AI/Weekly review/` (ถ้ามี) เพื่อรู้ว่าข้อไหนยังค้างจากสัปดาห์ก่อน

## 1. เก็บรายการโน้ตทั้งหมด
`list_notes` (vaultId, `limit` 200, ตาม `nextCursor` จนเป็น null) เก็บ `docId`, `relPath`, `title`, `updatedAt` ไม่นับโน้ตใน `_AI/Weekly review/`
วันนี้ = วันที่ตามเวลาไทย

## 2. หา 5 อย่าง
1. **เปลี่ยนในสัปดาห์นี้:** `updatedAt` ภายใน 7 วัน จัดกลุ่มตามโฟลเดอร์
2. **เก่าเกิน 90 วัน:** `updatedAt` เกิน 90 วัน ไม่นับ `Meetings/` และ `Decisions/` (เป็นบันทึกของวันนั้นอยู่แล้ว) เรียง `Products & prices`, `SOP`, `FAQ`, `00 Start here` ก่อน ใส่ในโน้ตไม่เกิน 15 รายการ ที่เหลือบอกเป็นจำนวน
3. **น่าจะซ้ำ:** ชื่อคล้ายกันเมื่อตัดวันที่ ตัวเลขท้ายชื่อ และคำว่า copy หรือ สำเนา ออก หรือชื่อเดียวกันคนละโฟลเดอร์ ตรวจคู่ที่น่าสงสัยด้วย `search_notes` (query = ชื่อโน้ต) และ `read_note` ทั้งสองโน้ต ไม่เกิน 10 คู่ ไม่นับ `Meetings/` และ `Decisions/`
4. **ขัดกัน:** `read_note` ทุกโน้ตใน `Products & prices/`, `SOP/`, `FAQ/`, `00 Start here` และ `Decisions/` ที่แก้ใน 90 วัน รวมไม่เกิน 40 โน้ต ถ้าเกิน ให้อ่านโน้ตที่เปลี่ยนสัปดาห์นี้และ `Products & prices/` ก่อน แล้วบอกว่าโน้ตไหนยังไม่ได้ตรวจ
   - ดึงข้อความที่เป็นตัวเลขหรือกติกา: ราคา (ตัวเลข + บาท) ส่วนลด (%) เงื่อนไข ระยะเวลา (เช่น ภายใน 24 ชม.) และใครอนุมัติ
   - สินค้าหรือเรื่องเดียวกันแต่ค่าไม่ตรงกัน = ขัดกัน
   - ถ้ามีการตัดสินใจที่มีวันที่ใหม่กว่าอธิบายการเปลี่ยนแล้ว ยังต้องใส่เป็น "โน้ตที่ยังไม่ได้แก้ตามการตัดสินใจ [[...]]"
5. **ช่องที่ยังว่าง:** โน้ตนอก `_AI/` ที่ยังมี `【กรอก:` หรือขึ้นต้นด้วยป้าย `> [ตัวอย่าง]` (ใช้ `search_notes` คำว่า "กรอก" และ "ตัวอย่าง" แล้วเช็กใน `read_note`)

ห้ามตัดสินเองว่าค่าไหนถูก

## 3. เขียนโน้ตรีวิว
1. `create_folder` (vaultId, name `Weekly review`, path `_AI/Weekly review`) ถ้ามีแล้วจะได้ `adopted: true` ใช้ต่อได้เลย
2. `create_note` ที่ `_AI/Weekly review/YYYY-MM-DD Weekly review.md` ถ้าชื่อนี้มีแล้ว ห้ามเขียนทับ (เจ้าของอาจติ๊กไปแล้ว) ให้ใช้ `YYYY-MM-DD Weekly review (2).md`
3. ใช้รูปแบบนี้ แทน `<...>` ด้วยของจริงจากข้อ 2 เท่านั้น หมวดไหนไม่มีรายการ ให้เขียนว่า "ไม่พบ"

```markdown
# Weekly review YYYY-MM-DD

ใช้เวลา 15 นาที ทำจากบนลงล่าง ติ๊ก [x] เมื่อเสร็จ ไม่ต้องครบทุกข้อ ข้อที่ค้างจะกลับมาในรีวิวสัปดาห์หน้า

## 1. ต้องตัดสินใจ (5 นาที)
- [ ] **<เรื่อง>:** [[<โน้ต 1>]] บอก <ค่า 1> แต่ [[<โน้ต 2>]] บอก <ค่า 2> ค่าที่ถูกคือ ______

## 2. โน้ตที่น่าจะซ้ำ (3 นาที)
- [ ] [[<โน้ต A>]] กับ [[<โน้ต B>]]: <ทำไมดูเหมือนเรื่องเดียวกัน> รวมเป็นโน้ตเดียว เก็บอันไหน ______

## 3. โน้ตเก่าเกิน 90 วัน (4 นาที)
- [ ] [[<โน้ต>]] แก้ล่าสุด <YYYY-MM-DD> (<N> วันก่อน) ยังถูกอยู่ไหม

## 4. ช่องที่ยังว่าง (1 นาที)
- [ ] [[<โน้ต>]]: <ช่องที่ยังว่าง หรือ ยังเป็นโน้ตตัวอย่าง>

## 5. เปลี่ยนในสัปดาห์นี้ (2 นาที อ่านผ่านๆ)
- **<โฟลเดอร์>:** [[<โน้ต>]], [[<โน้ต>]]

## ค้างจากสัปดาห์ก่อน
- [ ] <ข้อที่ยังไม่ได้ติ๊กจาก [[<รีวิวครั้งก่อน>]]>

---
ตรวจเมื่อ YYYY-MM-DD จากโน้ตทั้งหมด <N> โน้ต อ่านละเอียด <M> โน้ต ยังไม่ได้ตรวจ: <รายการ หรือ ไม่มี>
ตัดสินใจแล้ว บอก AI ว่า "บันทึกผลรีวิวนี้" เพื่อให้ brain-writeback แก้โน้ตและบันทึกการตัดสินใจลง Decisions
```

## 4. รายงานในแชท
3-5 บรรทัด: ชื่อโน้ตรีวิว จำนวนรายการแต่ละหมวด และขั้นต่อไป: "วันศุกร์นี้เปิดโน้ตนี้ ใช้ 15 นาที เริ่มจากข้อ 1"

เมื่อเจ้าของตอบผลรีวิวในแชท ให้ใช้ brain-writeback บันทึกการตัดสินใจและแก้โน้ตตามที่เจ้าของสั่ง แล้วติ๊ก `[x]` ข้อนั้นในโน้ตรีวิวด้วย `edit_note`
