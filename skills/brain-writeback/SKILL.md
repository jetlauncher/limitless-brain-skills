# brain-writeback: บันทึกสิ่งใหม่กลับลงสมองบริษัท

ใช้เฉพาะ MCP tools ของ connector **Limitless Company Brain** (ใน Claude Code ชื่อจะเป็น `mcp__limitless-brain__<tool>`). ไม่ใช้ shell และไม่อ้าง path ในเครื่อง

## อ่านก่อน
1. `list_vaults` เพื่อได้ `vaultId`
2. `list_notes` (vaultId, pathPrefix `_AI/How to use this brain`) แล้ว `read_note` ทำตามกฎในโน้ตนั้น ถ้าขัดกับ skill นี้ ให้กฎในโน้ตชนะ
3. ถ้ายังไม่ได้อ่าน `00 Start here/00 Start here` ในบทสนทนานี้ ให้อ่านด้วยวิธีเดียวกัน
4. ไม่มีสองโน้ตนี้ ให้แนะนำผู้ใช้รัน brain-setup ก่อน

## ทำเมื่อไร
ท้ายงาน ถ้าบทสนทนามีอย่างน้อยหนึ่งอย่าง: ข้อเท็จจริงใหม่ของบริษัท การตัดสินใจ คำถามที่ได้คำตอบแล้ว ขั้นตอนใหม่ หรือข้อมูลที่เปลี่ยน
ไม่มีของใหม่ ไม่ต้องทำอะไรและไม่ต้องรายงาน

## ขั้นตอน
1. ทำรายการสิ่งที่จะบันทึก ข้อละ 1 บรรทัด
   - ผู้ใช้พูดเองหรือยืนยันแล้ว: บันทึกได้เลย
   - AI สรุปหรือเดาเอง: ถามยืนยันครั้งเดียว รวมทุกข้อ
   - ราคา ส่วนลด นโยบาย: บันทึกเฉพาะเมื่อเจ้าของ หรือคนที่เจ้าของมอบหมาย สั่งในบทสนทนานี้
2. แต่ละข้อ `search_notes` (vaultId, ลองคำค้น 2-3 แบบ) แล้วเลือกโน้ตตามตารางโฟลเดอร์ในกฎ
3. มีโน้ตแล้ว: `read_note` แล้ว `edit_note` พร้อม `expectedRevision`
   - แก้ของเดิม: `replace` ข้อความเดิมแบบตรงตัว แล้วต่อท้ายว่า "(เปลี่ยนเมื่อ YYYY-MM-DD จากเดิม: ...)"
   - เพิ่มของใหม่: `insert_after` หัวข้อที่เกี่ยวข้อง
   - ถูกปฏิเสธ `stale_revision`: อ่านใหม่ แล้วลองอีกครั้ง
   - ถูกปฏิเสธ `anchor_not_found`: อ่านใหม่ แล้วคัดลอก anchor จากโน้ตแบบตรงตัว
4. ยังไม่มีโน้ต: `create_note` ในโฟลเดอร์ที่ถูก ตั้งชื่อตามกฎ (ถ้าโฟลเดอร์ยังไม่มี ใช้ `create_folder` ก่อน)
5. การตัดสินใจ: สร้าง `Decisions/YYYY-MM-DD <เรื่อง>.md` ตามรูปแบบข้างล่าง แล้วแก้โน้ตที่ได้รับผล (SOP, FAQ, Products & prices) ให้ตรงกัน พร้อมลิงก์ `[[...]]` ถึงกัน
6. รายงานสั้น 1-3 บรรทัด: บันทึกอะไร ไว้ที่โน้ตไหน และอะไรที่ไม่ได้บันทึกเพราะอะไร

วันที่ใช้ `YYYY-MM-DD` ปี ค.ศ. ตามเวลาไทย ไม่แน่ใจวันที่ให้ถาม

## รูปแบบโน้ตการตัดสินใจ
```markdown
# YYYY-MM-DD <เรื่อง>

- **วันที่ตัดสินใจ:** YYYY-MM-DD
- **ตัดสินใจว่า:** ...
- **ใครตัดสิน:** ...
- **เหตุผล:** ... (ไม่รู้ให้เขียน "ไม่ได้ระบุ")
- **มีผลตั้งแต่:** YYYY-MM-DD
- **โน้ตที่แก้ตาม:** [[...]]
- **ที่มา:** บทสนทนากับ AI / ประชุม [[...]] / ...
```
ถ้าการตัดสินใจนี้แทนของเก่า ให้ใส่ "แทน [[ชื่อโน้ตเก่า]]" และแก้โน้ตเก่าเพิ่มบรรทัด "ถูกแทนด้วย [[ชื่อโน้ตใหม่]]"

## ห้าม
- ห้ามสร้างโน้ตซ้ำเรื่องเดิม
- ห้ามใช้ `update_note` กับโน้ตที่มีอยู่แล้ว ใช้ `edit_note` เท่านั้น
- ห้ามบันทึกรหัสผ่าน เลขบัตร เลขบัญชี หรือข้อมูลส่วนตัวของลูกค้า
- ได้ `no_access` หรือ `read_only`: บอกผู้ใช้ว่าบัญชีนี้ไม่มีสิทธิ์แก้โน้ตนั้น แล้วเขียนข้อความสั้นๆ ที่ผู้ใช้คัดลอกส่งให้เจ้าของได้
