# faq-from-chats: อัปเดต FAQ จากแชท LINE OA

ใช้เฉพาะ MCP tools ของ connector **Limitless Company Brain** (ใน Claude Code ชื่อจะเป็น `mcp__limitless-brain__<tool>`). ไม่ใช้ shell และไม่อ้าง path ในเครื่อง

## กฎเหล็ก
- **ห้ามแก้ราคา ส่วนลด หรือนโยบายเอง** ไม่ว่าในโน้ตไหน ถ้าขัดกัน ให้ส่งรายการให้เจ้าของตัดสิน
- ห้ามคัดลอกชื่อลูกค้า เบอร์โทร ที่อยู่ LINE ID เลขพัสดุ หรือเลขบัญชี ลงโน้ต

## อ่านก่อน
1. `list_vaults` เพื่อได้ `vaultId`
2. `list_notes` (pathPrefix `_AI/How to use this brain`) แล้ว `read_note` ทำตามกฎในนั้น
3. อ่าน `00 Start here/00 Start here` ด้วยวิธีเดียวกัน
4. `list_notes` (pathPrefix `Products & prices/`) และ (pathPrefix `SOP/`) แล้ว `read_note` ทุกโน้ต ถ้ารวมเกิน 15 โน้ต อ่านเฉพาะที่ `search_notes` บอกว่าตรงกับเรื่องในแชท
5. `list_notes` (pathPrefix `FAQ/`) เก็บรายชื่อโน้ต FAQ ทุกหมวด

## 1. อ่านแชท
- แชทยาวมาก ให้ทำทีละช่วง แล้วรวมผล
- ข้ามคำทักทาย สติกเกอร์ และข้อความส่วนตัว
- ดึงแต่ละคำถามออกมา: คำถามแบบเขียนใหม่ให้สั้นชัด, คำที่ลูกค้าใช้จริง 2-3 แบบ (ไม่มีข้อมูลส่วนตัว), คำตอบที่แอดมินตอบ (ถ้ามี), และจำนวนครั้งที่ถาม
- รวมคำถามที่ความหมายเดียวกันเป็นข้อเดียว

## 2. เทียบทีละคำถาม
`search_notes` (vaultId, query = คำถาม) แล้ว `read_note` โน้ต FAQ ที่เจอ จากนั้นทำตามตาราง:

| เจออะไร | ทำอะไร |
|---|---|
| FAQ มีแล้ว และตรงกับที่แอดมินตอบ | เพิ่มคำที่ลูกค้าใช้แบบใหม่ใน "ลูกค้ามักถามว่า" ถ้ามี |
| FAQ มีแล้ว แต่แอดมินตอบไม่ตรง | ไม่แก้ ใส่ในรายการ "ให้เจ้าของตัดสิน" |
| FAQ ยังไม่มี และคำตอบแอดมินตรงกับ SOP หรือ Products & prices | เพิ่มคำถามใหม่ สถานะ "ยืนยันแล้ว" พร้อมที่มา |
| FAQ ยังไม่มี แอดมินตอบ แต่ไม่มีโน้ตไหนให้เทียบ | เพิ่มคำถามใหม่ สถานะ "รอเจ้าของยืนยัน" |
| ยังไม่มีใครตอบ หรือแอดมินไม่รู้ | เพิ่มคำถาม คำตอบ "ยังไม่มีในสมองบริษัท" สถานะ "รอเจ้าของตอบ" |
| คำตอบในแชทหรือใน FAQ ขัดกับ Products & prices หรือ SOP | ไม่แก้ทั้งสองฝั่ง ใส่ในรายการ "ให้เจ้าของตัดสิน" |

ปรับคำตอบใน FAQ ได้เฉพาะเมื่อไม่เปลี่ยนตัวเลขหรือเงื่อนไข เช่น เติมรายละเอียดที่ตรงกับ SOP หรือเติมข้อที่เคยเป็น "ยังไม่มีในสมองบริษัท" ด้วยข้อมูลที่ตอนนี้มีใน SOP แล้ว ส่วนการเปลี่ยนตัวเลขหรือเงื่อนไขทุกกรณี ให้ใส่ในรายการ "ให้เจ้าของตัดสิน"

## 3. เขียน FAQ
- เก็บในโน้ตหมวด `FAQ/FAQ <หมวด>.md` (เช่น `FAQ ราคา & ส่วนลด`, `FAQ การจัดส่ง`, `FAQ การชำระเงิน`) ใช้หมวดเดิมก่อน ไม่มีหมวดที่ใช่จึงสร้างใหม่
- คำถามใหม่: `read_note` แล้ว `edit_note` (`expectedRevision`) แบบ `insert_after` ท้ายคำถามสุดท้ายของหมวด หรือ `append_note` (พร้อม `idempotencyKey`)
- แก้คำถามเดิม: `edit_note` แบบ `replace` เฉพาะบรรทัดที่เปลี่ยน แล้วแก้ "อัปเดตล่าสุด"
- `stale_revision` หรือ `anchor_not_found`: อ่านใหม่แล้วลองอีกครั้ง

รูปแบบหนึ่งคำถาม:
```markdown
## <คำถาม>
- **คำตอบ:** ...
- **ลูกค้ามักถามว่า:** ..., ...
- **ที่มา:** [[SOP ...]] หรือ แชท LINE OA สัปดาห์ YYYY-MM-DD
- **สถานะ:** ยืนยันแล้ว / รอเจ้าของยืนยัน / รอเจ้าของตอบ
- **อัปเดตล่าสุด:** YYYY-MM-DD
```

## 4. รายงานเจ้าของ
ตอบในแชทตามลำดับนี้:
1. สรุป: อ่านแชทช่วงวันที่เท่าไร คำถามกี่ข้อ เพิ่มใหม่กี่ข้อ ปรับกี่ข้อ
2. คำถามที่ถามบ่อยที่สุด 5 อันดับ พร้อมจำนวนครั้ง
3. **ให้เจ้าของตัดสิน** เป็นตาราง: ข้อ | คำถาม | แชทตอบว่า | สมองบริษัทบอกว่า (ชื่อโน้ต) | ต้องเลือก
4. คำถามที่ "รอเจ้าของตอบ" และ "รอเจ้าของยืนยัน"
5. ปิดท้ายว่า: "ตอบในแชทนี้ได้เลย เช่น ข้อ 1 ใช้ราคาใน SOP"

เมื่อเจ้าของตอบ ให้ทำตาม brain-writeback: บันทึกการตัดสินใจลง `Decisions/YYYY-MM-DD <เรื่อง>.md` แล้วแก้ FAQ, SOP หรือ Products & prices ตามที่เจ้าของสั่งเท่านั้น
