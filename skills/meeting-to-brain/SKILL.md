# meeting-to-brain: บันทึกประชุมลงสมองบริษัท

ใช้เฉพาะ MCP tools ของ connector **Limitless Company Brain** (ใน Claude Code ชื่อจะเป็น `mcp__limitless-brain__<tool>`). ไม่ใช้ shell และไม่อ้าง path ในเครื่อง

## อ่านก่อน
1. `list_vaults` เพื่อได้ `vaultId`
2. `list_notes` (pathPrefix `_AI/How to use this brain`) แล้ว `read_note` ทำตามกฎในนั้น
3. อ่าน `00 Start here/00 Start here` ด้วยวิธีเดียวกัน (ใช้หัวข้อ "ใครดูแลเรื่องอะไร" จับคู่ชื่อคน)
4. ไม่มีสองโน้ตนี้ ให้แนะนำผู้ใช้รัน brain-setup ก่อน

## 1. อ่านประชุม
จากข้อความที่ผู้ใช้วาง หา:
- วันที่ประชุม (ไม่ใช่วันนี้ หาไม่เจอให้ถาม) แบบ `YYYY-MM-DD` ปี ค.ศ.
- หัวข้อสั้น ไม่เกิน 6 คำ ห้ามมีตัว `/ \ : * ? " < > |`
- ผู้เข้าร่วม และที่มา (Fathom, Plaud, Zoom หรือจดเอง)

แยกเป็น 4 กอง:
- **การตัดสินใจ:** สิ่งที่ตกลงกันแล้วชัดเจน ไม่ใช่แค่ไอเดีย ถ้าไม่แน่ใจให้ใส่กอง "ยังค้าง"
- **งานที่ต้องทำ:** ใคร ทำอะไร เสร็จเมื่อไร
- **คำถามที่ได้คำตอบ:** เรื่องที่ลูกค้าหรือทีมน่าจะถามอีก
- **ยังค้าง:** คำถามหรือเรื่องที่ยังไม่ได้ข้อสรุป

## 2. เทียบกับของเดิม
- การตัดสินใจแต่ละเรื่อง: `search_notes` ว่ามีใน `Decisions/` แล้วไหม และขัดกับ SOP, Products & prices หรือ FAQ ไหม
- `list_notes` (pathPrefix `Team/`) หาโน้ตของแต่ละคน เทียบทั้งชื่อเล่นและชื่อจริง
- `list_notes` (pathPrefix `Meetings/<วันที่ประชุม>`) กันโน้ตประชุมซ้ำ

## 3. แสดงแผนก่อนบันทึก
บอกผู้ใช้สั้นๆ ว่าจะสร้างหรือแก้โน้ตไหนบ้าง และเรื่องที่ขัดกับของเดิม (เช่น ราคาที่พูดในประชุมไม่ตรงกับ SOP) แล้วถามครั้งเดียวว่า "บันทึกตามนี้เลยไหม"
ถ้าผู้ใช้สั่งให้บันทึกเลยตั้งแต่แรก ข้ามการถามได้ ยกเว้นมีเรื่องที่เปลี่ยนราคาหรือนโยบาย

## 4. บันทึก ตามลำดับนี้
1. **โน้ตประชุม:** `create_note` ที่ `Meetings/YYYY-MM-DD <หัวข้อ>.md` ตามรูปแบบข้างล่าง ถ้ามีชื่อนี้แล้วและเป็นประชุมเดียวกัน ให้ `edit_note` เติมโน้ตเดิม ถ้าคนละประชุม ให้ต่อท้ายชื่อว่า ` (2)`
2. **การตัดสินใจ:** เรื่องละโน้ต `Decisions/YYYY-MM-DD <เรื่อง>.md` ใช้วันที่ประชุม ตามรูปแบบข้างล่าง ถ้าแทนการตัดสินใจเก่า ให้ลิงก์ถึงกันทั้งสองโน้ต ถ้าเปลี่ยนราคาหรือนโยบาย ให้แก้ SOP, Products & prices และ FAQ ที่เกี่ยวข้องด้วย `edit_note` (เฉพาะเมื่อผู้ใช้ยืนยันในข้อ 3 แล้ว)
3. **งาน:** ในโน้ต `Team/<ชื่อเล่น>.md` เพิ่มบรรทัดใต้หัวข้อ `## งานที่ต้องทำ`:
   `- [ ] <งาน> (กำหนดส่ง: YYYY-MM-DD หรือ ไม่ได้ระบุ) จาก [[YYYY-MM-DD <หัวข้อ>]]`
   - มีหัวข้อนี้: `edit_note` แบบ `insert_after` anchor `## งานที่ต้องทำ`
   - ไม่มีหัวข้อนี้: `append_note` ทั้งหัวข้อและบรรทัดงาน พร้อม `idempotencyKey`
   - ยังไม่มีโน้ตของคนนี้: `create_note` ตามรูปแบบโน้ตคนในทีมข้างล่าง
   - ไม่รู้ว่าใครรับงาน: ใส่ไว้ในโน้ตประชุมใต้ "งานที่ยังไม่มีเจ้าของ"
4. **FAQ:** `list_notes` (pathPrefix `FAQ/`) หาหมวดที่ใช่ คำถามเดิมมีแล้ว ให้แก้คำตอบถ้าเปลี่ยน (ใส่วันที่) คำถามใหม่ ให้เพิ่มหัวข้อในโน้ต `FAQ <หมวด>` ไม่มีหมวดที่ใช่ ให้สร้างโน้ตหมวดใหม่ รูปแบบหนึ่งคำถาม:
   ```markdown
   ## <คำถาม>
   - **คำตอบ:** ...
   - **ลูกค้ามักถามว่า:** ...
   - **ที่มา:** [[YYYY-MM-DD <หัวข้อประชุม>]]
   - **สถานะ:** ยืนยันแล้ว
   - **อัปเดตล่าสุด:** YYYY-MM-DD
   ```
ใช้ `read_note` ก่อนแก้ทุกครั้ง และส่ง `expectedRevision` ทุกครั้งที่ใช้ `edit_note`

## 5. รายงาน
บอกผู้ใช้: โน้ตประชุมอยู่ที่ไหน, การตัดสินใจกี่เรื่อง, งานของใครบ้าง, FAQ ที่เพิ่มหรือแก้, และเรื่องที่ยังค้าง

## รูปแบบโน้ตประชุม
รูปแบบข้างล่างทุกแบบไม่มีบรรทัดหัวข้อ `# ชื่อโน้ต` เพราะแอปแสดงชื่อไฟล์เป็นชื่อโน้ตอยู่แล้ว ห้ามเติมเอง
```markdown
- **วันที่:** YYYY-MM-DD
- **ผู้เข้าร่วม:** ...
- **ที่มา:** Fathom / Plaud / Zoom / จดเอง

## สรุป
3-5 บรรทัด

## การตัดสินใจ
- [[YYYY-MM-DD <เรื่อง>]]

## งานที่ต้องทำ
- [ ] <ชื่อ>: <งาน> (กำหนดส่ง: ...)

## งานที่ยังไม่มีเจ้าของ

## คำถามที่ได้คำตอบ

## ยังค้าง
```
อย่าวาง transcript เต็มลงโน้ต เก็บเฉพาะสรุปและประโยคสำคัญไม่เกิน 3 ประโยค เว้นแต่ผู้ใช้ขอ

## รูปแบบการตัดสินใจ
```markdown
- **วันที่ตัดสินใจ:** YYYY-MM-DD
- **ตัดสินใจว่า:** ...
- **ใครตัดสิน:** ...
- **เหตุผล:** ... (ไม่รู้ให้เขียน "ไม่ได้ระบุ")
- **มีผลตั้งแต่:** YYYY-MM-DD
- **โน้ตที่แก้ตาม:** [[...]]
- **ที่มา:** ประชุม [[YYYY-MM-DD <หัวข้อ>]]
```

## รูปแบบโน้ตคนในทีม
```markdown
- **ชื่อเต็ม:** 【กรอก: ชื่อเต็ม】
- **หน้าที่:** 【กรอก: หน้าที่】

## งานที่ต้องทำ

## งานที่เสร็จแล้ว
```

## ห้าม
- ห้ามแต่งการตัดสินใจหรือกำหนดส่งที่ไม่มีในประชุม
- ห้ามเก็บเบอร์โทร ที่อยู่ เลขบัญชี หรือข้อมูลส่วนตัวของลูกค้าที่พูดถึงในประชุม
